# R21 submission-freeze 修改方案

依据：2026-09-05 Reviewer 2审查及当前submission-ready PDF。目标是闭合可成立的拒稿路径，保留现有有效证据。此文件是修改方案；论文、代码、主实验和冻结数据尚未按此方案修改。

## 总体路线

推荐“核心论证补齐 + 现有数据复核”。不建议仅添加bounded免责声明，也不建议新开一轮更大模型/数据库/真实用户实验。

顺序：**A 理论闭合 → B novelty差异 → E统一叙事 → F冻结验收**。C测量复核与D授权时点可在逻辑上独立开展，结果均先于E。这里描述依赖关系，不自动启动其他任务或子代理。

## A. P0：先修C2，再决定能保留多强的理论贡献

### A1 固定证明对象

修改位置：Section3.2–3.3，Table2；涉及 `paper/sections/03-problem-contract.tex`。

需要明确：

1. 历史域H：合法历史、非法请求、违规后继和事后篡改历史是否都属于同一域；哪些结构事实对所有历史成立。
2. O是规范性结果还是实际运行结果；允许安全执行拒绝非法请求时，不能把“请求非法”与“执行不安全”混用。
3. 每个观察函数具体返回什么；允许读取什么对象、解引用哪些句柄、推导哪些关系。
4. 观察是在准入前还是追踪时取得；禁止将待判定的complete/incomplete标签作为输入泄露答案。
5. candidate identity、授权cid、transition、source map的交叉关系。类别可以有重叠，但不能默认删一个标签就删掉所有可恢复信息。

产物：一张观察定义表，列“类、原始可见对象、可推导信息、隐藏内容、时点”。定义应源于实际问题和接口，不以让命题成立为唯一理由。

### A2 提供五对真正可检查的历史

每一对均交付：安全/不安全的规范标签、完整历史、五类观察值、剩余四类相等检查、完整观察能够区分的检查。按当前定义约定是否允许身份重命名；若允许，应使用一致的双射，不能逐关系任意重命名。

优先处理DV：改变候选100为101会改变内容及证书身份，可能被DC区分。其次处理DB/DS：遗漏批次效果可能改变来源关系。再处理DF与版本链的交叉可推导性。

验证可以采用明确的逐项数学推导；如使用可执行模型，把高层双历史观察检验单独加入小型检查文件，不修改历史66条Alloy命令来伪装成它们已验证该命题。

**验收：**对每一类，H内确有历史对，O不同，且全部剩余观察相同；相关观察定义与实际允许的读取/推导一致。存在witness和完整模型拒绝非法请求分别报告。

### A3 无法通过时的处理分支

- 若只是定义缺失，补齐定义并给出正确构造。
- 若发现某类可从其他类恢复，明确否定当前独立不可冗余说法，研究是否只能得到局部必要性或规则敏感性。
- 可将C2收窄为“固定观察接口下的区分结果”，但要解释固定接口的现实意义，不声称任意表示下的信息必要性。
- 若只能保留“需求组织 + 编码消融”，撤回basis/individually irredundant等未建立表述，并回到B评估剩余贡献；不能把降级后投稿可接受视为已确定。

**禁止做法：**直接把规范结论塞进观察元组；通过定义“只有di不同”把待证结论当假设；删除DC时悄悄一并删掉其它类原本可见的信息却不披露。

### A4 区分证据层级

Section4.2/4.3、Table4、RQ2分别写清：

- 高层命题：双历史观察等价下的区分能力。
- 现有十一消融：低层约束对选定非法请求的敏感性。
- Full assertions：编码scope内的保持性/分离证据。
- 九投影及二十mutants：选定形式—具体对应。

新检查单独列分母。不能把新witness并入66/66或9/20旧分母。

## B. P0/P1：让novelty落在关系上

修改位置：Introduction C1/C2、Section2.1、Table1；`01-introduction.tex`和`02-related-work.tex`。

使用一个贯穿实例：旧权威值90，机器提议100，人授权101；另一个未变字段保持原来源。

| 关系 | 需要说明的问题 |
|---|---|
| 旧值90 → 新权威值101 | 与一般authorized mutation有什么相同点 |
| 机器候选100 → 人授权101 | 哪个不可变对象证明人针对的是这条候选 |
| 授权101 → commit101 | 批准的值如何约束实际后继 |
| 未变字段 → 原source | 完整后继为什么不仅是一次字段写入 |

对Continuity Kernel、LatticeMind、MemTxn给出原生对象/关系映射和所需扩展；用原论文具体段落支持“未定义/未报告”，不要将其写成“不可能实现”。MutMem的old/new与proposal/authorized两个维度应明确区分。

**验收：**读者能说清本文增加哪条语义义务；论证不依赖SQLite、工具名字、测试数量或“AI”标签。若A降级，B必须同步重新评价，而非原样保留理论新颖性说法。

## C. P0：修实验解释，优先重用现有记录

修改位置：Section7.3、8.8、9.5，Table13–15，Fig.4；`07-evaluation-protocol.tex`、`08-results.tex`、`09-discussion-threats.tex`及表图生成入口。

### C1 先做host依赖表，按需做对照

把A1–A10逐项列为：模型可调用什么、host实际调用什么、哪个输入来自prepared fixture、哪个来自agent output、何时读取before/after digest。

已核查的结果构成：A2–A9共有720次authority-evaluable固定host挑战；A1/A10共179次capability-unavailable场景。后者不能写成真实执行了179次越权API请求。聚合0/899可保留为原定义指标，但正文同时分解构成。

**对照触发条件：**若数据流和代码已足以证明某分支不依赖agent evidence，依赖表即可，不为增加“实验数量”重复跑。只有对间接副作用或proposal导致的状态差异仍不清楚的路径，才在临时库重放空、正常及对抗evidence，保持相同初始状态，记录候选状态与权威状态变化。

不开放FactAdmissionPort给模型。对照不用于宣称新攻击覆盖，而用于确定RQ8究竟检验了哪条联系。

**验收：**Abstract、RQ8、Fig.4均不再暗示899次模型生成攻击；“authority invariance”明确是执行总体内的并置观察，不是因果或非干扰定理。

### C2 核查recognition的语义有效性

保持原frozen scorer和原始日志不动，新增analysis版本。

范围为四类场景：context=A2+A3，stale=B4+A6。当前统计对应174个context-evaluable和151个stale-evaluable，共325个待审行为结果（四类场景共360个planned runs）。正式导出时重新核对唯一run id、缺失状态和分母。

先固定rubric再审阅：必须准确指出当前候选与目标上下文/版本的关系；只复述题目、否定词匹配、泛化警告、不相关引用不算识别。允许同义表达。明确观察agent最终回答还是工具调用及理由，不能事后择优混用。

导出审阅表：run_id、scenario、原文本、工具证据、原判定、语义判定、依据、歧义原因、标注者和时间。隐藏model_config_id进行首次语义判定；如由AI辅助预标注，披露方法，由实际研究者确认疑难样本，不能声称有未参与的人类评审者。

小型样本仅能作为排查；若要以语义指标替换所有分子，应按统一rubric核查全部相关可评结果。输出旧/新评分混淆矩阵、否定/回显/同义表达的差异类型及各配置新统计。

**处理分支：**

- 若核查支持主要模式，保留经验证的语义指标，并披露原评分与验证程序。
- 若变化较大，如实更新Table14、Fig.4和C4解释，不选择能保留原趋势的rubric。
- 若不进行完整语义核查，只能将原指标明确称为lexical cue proxy，撤回相应语义recognition解释；不能仅更名后原样宣传认知差异。

### C3 澄清runtime与端点的交叉

新增一张小表，不删除现有合法记录：93个terminal runtime failures中，64个仍有authority verdict；3个仍可行为评分且completion=false。terminal class与endpoint evaluability不是互斥分区。

保留320/335为原条件completion endpoint；可补320/360=88.89%为planned benign yield，但必须使用不同名称。不能把runtime failure自动当成safe，也不能把已有真实host verdict因runtime标签而抹去。

### C4 处理0.33%的解释

推荐在Abstract与Fig.4主图突出0/899和场景分解，将0.33%移到方法或表注，并称为声明binomial假设下的参考区间。固定、异质、部分确定性host工作负载不能用该数字量化未知漏洞概率。

不声称换成cluster bootstrap就能解决0事件和未知失效族问题。若无法给出恰当的抽样推断对象，则删除风险上界解释，保留观测计数与覆盖范围。

**C整体验收：**325条行为核查有可追溯输出或明确代理降级；899的生成过程可复述；端点交叉表与原1260行一致；所有更新由版本化分析生成，无手工修改生成表数字。

## D. P1：明确授权时点，默认不扩展实现

修改位置：Section3.5/Table3 P3、Section5.1/5.3、Section9.4。

推荐与现有实现一致的语义：操作在事务内的policy check获得授权判定；此前已生效的撤权拒绝该操作；与已开始操作重叠的撤权，不承诺取消该在途提交。限定在该prototype的内存policy范围，不声称跨进程全局撤权。

把“allowed at commit”改成明确的判定时点及在途语义。保留本次已复现的before-CAS/before-commit撤权结果作为边界说明，不能称强撤权测试通过。

只有作者需要“revoke完成后任何在途提交也不得生效”的强语义时，才进入实现补丁：授权策略版本/锁与提交共享序列化，再做并发撤权与竞争提交测试。这条扩展不是当前默认任务。

**验收：**P3、TCB、实现说明和已有探针能同时为真；不以“host可信”回避一个未定义的在途撤权保证。

## F. 冻结验收与停止条件

1. C2每项命题有可独立检查的定义和证据；若降级，Title/Abstract/C2/Fig.2/Conclusion全部同步，novelty重新判断。
2. 模型行为、host机制与runtime可靠性三层没有交叉误述；0/899不再被解释成899次模型攻击。
3. recognition的名字与评分对象一致；新旧分析可追溯，结果不依赖事后选择rubric。
4. P3时点和在途撤权语义与实现一致。
5. 论文编译无坏引用；检查更改涉及的图表、计数和附录；只运行与修改相关的形式检查、生成/验证命令。若未改核心实现，不为了形式完整重复所有付费实验。
6. 新投稿candidate与对应分析包单独存档；验证最终公开入口和revision manifests。旧R21公开存档已可访问，不把原可访问性批评重新列为问题。

满足以上条件后进入submission freeze，不再追加新模型、新数据库、OCR精度、生产部署或真实用户研究。
