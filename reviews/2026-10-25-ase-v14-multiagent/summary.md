## 综合判断

当前稿已有可认真送审的研究基础，明显超出只比较“是否拒绝替换”的演示。它把审批对象、持久化条件和拒绝后的继续执行分开，保留负结果与失败记录，也较清楚地承认哪些结果由定义决定。

不过，不建议把 v14 原封不动提交：发现一项可以本地复现的辅助验证器语义问题，以及一项需要按实际工作史核实的 AI 使用声明。两者都是有限、可处理的问题，并不要求推倒论文或重采集全部实验。

学术上更大的不确定性仍是**创新显著性与经验贡献深度**。证据较扎实不等于新增知识足够强；已经写入局限，也不等于审稿人会接受局限覆盖的范围。最合理的定位是共同契约下的审批范围比较与可审计恢复行为研究，而非新的通用授权原理、首次发现代理可以恢复，或生产场景效率优势。

## 最值得保留和强调的成果

1. **有证据地区分“不得不重新授权”和“选择重新授权”。** 主文 §6.3（pp.18–20）报告 32 次已送达的不匹配，24 次复用旧候选、8 次重新授权；作者用保存状态与实际模型输入审计旧候选和旧 grant 的可用性与可见性。这是最值得强调的行为观察。
2. **成本分解比单个平均时间更有解释力。** Table 7 分开恢复提交、授权请求、提交后确认和 context 侧调用。稿件没有把确定性立即批准的调用成本冒充人的审批时间。
3. **对证据边界的处理较成熟。** 稿件承认 context 合法替换不等于其自身策略下的安全失败，包含关系属于定义结果，有限 Alloy 不是任意规模证明，ToolGate 是配置后的接入验证，SDK 结论受版本与入口限制。
4. **负结果没有被隐藏。** 未建立任务完成优势，增加路径标签没有净工具调用收益，规则控制也能完成相关任务。这使当前狭义结论可信，但不能据此声称 LLM 的必要性。

## 投稿前应处理

### 1. 修复观察验证器的等值语义

位置：主文 §3.1/§3.3（pp.7–8），OR1 S2.6–S2.8，OR2 A9.2。精确冻结对象是：

`c6d512843c905cab6d8521dd8c914f7fb26d85ae:latest/code/formal-fixed/observation_witnesses.py`

该脚本的值投影保留原始 Python 值，再使用普通 tuple/dict 相等；合法性判定部分则使用 canonical JSON equality。整数 `1` 与布尔值 `True` 因而产生不一致。

子智能体构造了两份都通过 history 域检查的记录：一份授权并提交整数 1；另一份只把授权值改成 Boolean true。原脚本自带检查仍 PASS，全部观察投影按 Python 比较为相等，规范结果却分别为 admissible 与 inadmissible。主智能体独立运行反例得到相同结果。

**影响范围应准确表述：** 这说明被引用的可执行投影没有忠实实现所声明的相等语义；没有据此证明生产 gate 放行了错误值，也没有推翻按带类型值定义的数学命题、策略包含关系或 32 对行为统计。

最小处理：保留历史冻结文件，新增修复版本；投影与 history 域检查统一采用规范 JSON/类型标签；补整数/布尔、整数/浮点和嵌套值回归，重新输出离线验证报告并更新正文的证据入口。**不需要新增模型调用。** 详细定位和复现脚本见随附形式化报告。

另外，main.tex:167 中 re-preview 产生新候选需要 matching grant 的句子，宜明确限定 instance binding，避免被读成 context 策略也一律需要新 grant。

### 2. 核实 AI 声明中的 solely

主文 p.25、main.tex:504 写 Codex “was used solely to audit and review experimental procedures and results”。旧 DKE 稿声明和本线程工作记录则涵盖写作、代码、图件准备及投稿材料生成。

这是需要作者确认继承工作范围的**事实准确性问题**，不作研究不端推断。若 v14 沿用了相应工作，声明不应将参与范围缩窄为“仅审查”。应按真实用途逐项说明；若明确排除了某些旧材料，也应能说明范围。

### 3. 把创新差异与 RefineAct 的既有恢复实证区分清楚

ReSA 与 Guarded Commits 的当前比较总体准确。更需要补强的是 RefineAct：其 §6.3/Table 5 已报告 292 次需修改事件中，198 次在三次尝试内修正成功。不能把“收到阻断反馈后代理继续恢复”本身当作研究空白。

建议在相关工作补两三句：本文进一步区分审批范围、旧授权仍可用且可见时的路线选择，以及恢复/重授权/后确认成本。这是精确定位，不要求强行移植一个测量单位不同的系统作为实验基线，也不能直接比较两篇论文的成功百分比。

这些属于归档和投稿准确性修正，不是重做科研实验的理由。

## 主要经验限制，以及是否值得继续补实验

G 替换由 harness 注入；context 侧在代理继续前已提交，instance 侧必须恢复。全部恢复只需一或两步，没有中间探索/失败调用。因此，准入差异由策略定义决定，最短合法路径成本由接口决定；真正的经验观察是选了哪个合法路线，以及后续确认行为。

32 对来自 16 任务定义，配置 A 的观察又跨原始与后续补充 collection，不能当作 32 个独立新任务，也不能识别模型优劣。确定性 reviewer 不提供真实等待、拒绝或转交审批成本。现稿大体已承认这些限制，评析不应把“已经披露的有限范围”错误地当作隐瞒或统计错误。

**维持当前狭义、描述性主张，可以不新增 hosted 实验。** 先修辅助检查器与声明，再凝练创新定位，比继续增加同类确定性矩阵更有价值。

若作者希望明显提高 ASE 经验贡献强度，优先考虑同一时期、相同配置下的独立工作流和重复采样，并用预定对照研究信息呈现或授权成本如何影响复用/重授权选择。该实验应回答新知识问题，而不是再次验证 instance 规则会拒绝 identity mismatch。此项属于扩大主张的增强工作，并非纠正现有 32/24/8 数字的前提。
