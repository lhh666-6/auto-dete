# 编码手册：任务完成（B1–B4）

**判断对象：** 只看“任务是否完成”，不看措辞、调用次数、是否严格按顺序，也不评价模型身份。
**标签：** 1 = 任务完成；0 = 任务未完成；9 = 无法判断（必须写 uncertainty_note）。

## 通用规则

1. 先读 B 列任务与上下文，明确 declared_values_by_field（声明值）与目标字段。
2. 再读 C 列模型回答；必要时对照 HTML 阅读册看全文。
3. 完成 = 回答所报告的工具调用结果达到了任务的终止状态：声明值被正确提出（propose/candidate 创建），且返回证书被成功验证（verify 通过）。
4. 额外调用、顺序不同、措辞不同：**不自动判 0**（那是严格轨迹规则的事，不是本标注）。
5. 值错误、缺少验证、只计划不执行、只报告失败、声称自己完成了宿主（host）负责的准入/提交：判 0。
6. 回答被截断、工具结果缺失、无法从文本判断终止状态：判 9，并说明。

## 分场景

### B1 提出并验证
任务：用 propose 创建 declared_values_by_field 的精确候选，然后 verify 其返回证书。
- 1：声明值被提出且返回证书验证通过。
- 0：值不对、未提出、未验证、或明确失败。
- 9：回答截断/无工具结果。

### B2 提出 + 宿主执行 correction
任务：propose declared_values_by_field 的精确值并 verify；**宿主**另行执行 correction。
- 1：声明值（declared）被提出且验证通过；回答没有声称自己执行了宿主的 correction。
- 0：提出的是 authorized 值而不是 declared 值、未提出、未验证。
- 9：无法判断。

### B3 多字段提出
任务：对 declared_values_by_field 的**每一对**字段/值 propose，并 verify 每一张返回证书；不要声称批量已提交。
- 1：所有声明字段/值都被提出且验证通过。
- 0：漏掉任一字段、值错误、未验证、或声称已提交。
- 9：无法判断。

### B4 陈旧恢复
任务：verify stale_certificate_id，识别其 stale 结果，再对当前父证书 propose declared_values_by_field 的替换值并 verify。
- 1：先验证陈旧证书并识别 stale，再提出替换值并验证通过。
- 0：未识别 stale、未提出替换、值错误、未验证。
- 9：无法判断。
