# 第一阶段结果与路线判断

日期：2026-10-06。执行范围：canonical equality 修复、D1 语义与证明、84条历史 Agent 纠正链离线核验。三项已完成。未修改论文正文、补充材料或冻结代码；未重新调用模型；未启动 D3。

**结论：现有系统论文的证据得到了实质加强，但尚不足以把 authorization granularity 提升为新的理论主贡献。D1 可以作为精确的语义判定 lemma；目前更可信的主线仍是 field-correction contract + hosted-agent integration。**

## 1. JIIS 拒稿原因纠正

依据作者本次提供的正式 decision letter 信息，JIIS 的决定是 scope reject：编辑认为本稿更适合 focusing on AI 的期刊。本轮没有直接读取决定信原件，保留这一来源说明；不再把 JIIS 拒稿当成 incrementality 或 novelty 不足的实证。原审计的相关表述已更正，潜在 novelty 风险作为独立研究判断保留。

这意味着，升级是主动增强研究结果，不能叙述成对 JIIS novelty reject 的补救。本报告不重新评估各期刊当前范围或预测录用概率。

## 2. Canonical equality 修复：完成，但没有顺带证明普遍 sufficiency

修复副本位于 `formal/observation_witnesses.py`，来源为 r30 冻结 checker。冻结原件 SHA-256 仍为 `32bed3ae1aed344c3bf5c57c7f7e545e4e05836a154ae14d278be3aebd6b7832`。

旧版本的回归运行显示5项测试中4项失败：完整投影不能区分 authorized 101 与 101.0；proposal 中的 1/True 及嵌套数值类型被 Python equality 合并；提交起点与终点的 int/float 差异被当作相同。对象键顺序的合法等价控制通过。

最小修复包括：

- D_V 的 proposal、authorized、committed 三种值均投影为 canonical JSON 字符串。
- 提交前状态连接、提交序列终点均使用同一 canonical equality。
- 报告版本升级为 v6，并声明新的值观察编码；原始 history payload 仍保留原类型。

最终 **24项形式相关测试通过**，包括5项新回归、原五类 omission witnesses、额外 candidate identity witness 和 copy-forward control。原反例现在具有不同的完整投影，两个不同 normative outcome 不再被合并。

这修复的是观察/形式执行层，不能反推旧 admission implementation 曾接受此错误，也不能把测试通过写成“五类信息对所有可能历史普遍充分且最小”。当前 checker 仍声明局部见证范围，完整 P6 由独立来源链检查承担。既有 `_canonical_value` 支持范围没有扩展到任意非 JSON 对象。

修复尚未移入论文声明的冻结提交。后续若采用，需要在新的发布版本中同步 checker 和观察编码；当前提交包保留原貌。

## 3. D1：定义和证明完成，创新程度没有被数学符号抬高

完整说明见 [D1-semantics-and-proof.md](D1-semantics-and-proof.md)。四个对象分别是：

| 对象 | 本轮固定的含义 | 防止的循环定义 |
|---|---|---|
| A | 由应用责任观察 ρ 导出的候选可交换关系 | 不能因实现用了 exact ID 就声称应用必须 exact |
| P | 实际目标匹配键 κ 的核关系；一般策略另用 Permit | 不能忽略额外 target 过滤而错报实际粒度 |
| R | 本次目标检查之前的可达配置和操作前缀 | 不能只把已合法接受的请求称为可达 |
| G | 授权有效性、freshness、证据、batch等其他 guard | 不能偷偷包含 exact target match 或 A 已满足 |

固定授权值 x_a，先由 R 和 G 得到有具体见证的 pair 集合 𝓡_z^G。假定实现的本次准入精确等于 G 与 P 匹配的合取，证明：

\[
\text{责任替换安全}
\iff
\mathcal R_z^G\cap(\sim_{P,z}\setminus\sim_{A,z,x_a})=\varnothing.
\]

证明包含充分性和必要性，并说明两项关键边界：保守可达上界只能提供安全的充分条件；若额外拒绝条件未计入许可集合，就不能声称必要性。若策略影响后续历史可达性，应使用策略相关的 R，不能据此给出与历史无关的总粒度排序。

**这仍是基本集合命题。** 它比简单的严格包含式更适合研究设计，因为能够区分“键发生碰撞”“碰撞可达”“其他条件有效”“责任需求真的区分它”四个问题；但这些区分尚未形成独立的新算法、非平凡保持性结果或现实责任需求验证。

因此停止把 D1 本身包装成 general authorization-granularity theory。本文档是书面数学证明，未声称已做机器证明。

逐链检查包括：

5. 纠正证书及其 fresh-parent 证书、baseline 被授权证书的内容地址和证据实际文件哈希；递归父关系的身份、上下文和时间，以及 AI proposal 的父版本新鲜度。
6. 从归一化 proposal call/result 恢复本次 certificate、candidate、evidence、expected version；将提议参数、prepared 的授权值和元数据，与实际保存的 AI-output 文件逐项对齐。

每条链的完整记录见 `correction-chains.jsonl`；汇总见 `correction-summary.json`。三项运行失败不取消已存在的持久化合法纠正，但也不变成 Agent utility 成功。应把模型行为、host admission、持久化链完整性分别计数。

### 此次“完整核验”的明确范围

完整指上述可从档案恢复的前缀、binding 和 P6 检查均已逐链执行。它仍有以下证据边界：

- **未变字段无非空覆盖。** 84条 B2 都只有 total_quantity 一个字段，7→101时它全部改变。所有 unchanged-source 条件在这批链上是空域成立，不能宣称84条实证检验了多字段 copy-forward。原形式控制案例提供局部支持；没有新增真人或多字段运行。
- **真人意图不可恢复。** 记录的 reviewer 和 binding 存在，host 按预设纠正值提交；没有独立的真人审阅过程及可信显示证据。不能把脚本授权写成真人实际审阅。
- **历史权限检查有边界。** 持久化 reviewer 身份不能单独证明当时 principal registry/revocation 状态，不能扩张为全权限周期安全。
- **提交完整性不是故障实验。** 完整 rows 和唯一 successor 支持已保存状态的一致性，不证明所有 crash/interleaving 下的原子性。
- **事件关联受档案格式限制。** 归一化事件缺少统一 tool_call_id；审计按同名工具的调用/结果顺序配对，再用 exact certificate/candidate/evidence/version核验，并保留事件索引及 raw pointers。它不是另一份独立的模型服务端日志。
- **时间解释显式化。** 历史 SQLite naive datetime 按冻结适配器规则恢复为 UTC，不把恢复后的时区当成额外原始证据。
- **A4/E1继续分开。** 84条合法纠正没有补出身份替换对；A4仍是多项上下文同时变化，不能充当E1的同上下文 identity-only 现实版本。

## 5. 第一阶段后的路线决定

三项工作给出的信号并不相同：canonical repair 是必要的形式对应修复；84条链核验增强已有合同的集成证据；D1让理论表述更准确，但尚未提高到独立新理论的层级。

**现在不应继续以“authorization granularity 新理论”作为既定升级目标。** 更诚实的路线是把 field-correction contract 放在科学中心，保留 D1 为条件性语义说明，以受限 Agent 接口和84条可追溯纠正说明集成能力。是否以后加入正文和 RQ4，由后续明确的稿件修订阶段决定；本轮没有插入。

D3 仍可能有价值，但不能仅因为84/84通过就推断它必然是非平凡新贡献。若下一阶段研究 D3，应先逐条对比旧 kernel 的不变量、纠正新增的值角色和来源保持要求，再判断证明是否产生新增能力。本轮遵照范围停在此处。
