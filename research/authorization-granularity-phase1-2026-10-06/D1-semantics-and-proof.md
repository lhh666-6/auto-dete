# D1：可达替换下的责任粒度兼容性

日期：2026-10-06。状态：第一阶段独立研究说明；未进入论文正文。这里完成定义和证明，不声称建立了一项新的普遍授权理论，也不包含 D3 的历史归纳证明。

## 1. 先固定判定的对象

本命题判定的是：**一项已经发出的授权，在其他准入条件有效时，是否允许把审阅候选替换为责任规范所区分的另一候选。** 它不判定模型是否正确、真人是否充分审阅、系统是否抗所有攻击，也不自动证明连续历史的所有不变量。

固定环境 z：候选存储及其可写接口、证据解释、记录/字段域、授权发放流程、时钟和版本演化规则，以及待考察的提交前状态模型。固定一个显式授权值 x_a，按合同 canonical JSON 比较，故整数 101 和浮点 101.0 不相等。比较授权粒度时，保持 x_a、审阅者、授权有效期及其他约束不变；不得把“换候选同时改授权值”当成纯粒度替换。

候选宇宙 C_z 的成员是带不可变身份和元数据的候选实例，不是单个数值。授权 a 至少包含审阅候选 c_r、授权值 x_a、审阅者与有效性信息。提交前配置写作

\[
\sigma=(h,s,a,c_s),
\]

其中 h 是到提交前状态 s 的操作前缀，c_s 是本次请求提交的候选，尚未执行本次目标匹配和 commit。拒绝和接受都必须能够作为检查结果；不得仅从已接受请求生成候选配置。

## 2. A：独立的责任规范

先声明责任观察函数

\[
\rho_{z,x_a}:C_z\to Q_{z,x_a}.
\]

它给出应用要求保留的责任回答，例如“是哪一次机器提议接受了审阅并成为这次纠正的来源”。定义

\[
c_1\sim_{A,z,x_a}c_2
\iff \rho_{z,x_a}(c_1)=\rho_{z,x_a}(c_2).
\]

这是函数的核等价关系。其依据必须是事先声明的责任需求，不能是当前系统已经选择 exact ID，不能是“策略允许什么就认为什么负责”。

两种合法但不同的规范：

- 实例责任：ρ 包含被审阅的 candidate instance ID，必要时同时包含记录、字段和来源角色。不同实例即使提议值和其余上下文相同，仍被区分。
- 内容责任：ρ 只包含事先要求的记录、字段、canonical proposal、证据、生产者等内容，允许规范明确视为可交换的实例。

这两种规范都是研究假设；现有实验没有证明所有实际应用都应采用第一种。若应用要求的是有向授权范围而非可交换关系，应使用一般责任许可关系 A(c_r,c_s)，不能强行套等价类。下文的等价关系版本仅适用于可交换责任语义。

## 3. P：实际实现的目标匹配关系

对一族按相同目标键实现的策略，定义

\[
\kappa_{P,z}:C_z\to K_{P,z},\qquad
c_1\sim_{P,z}c_2\iff\kappa_{P,z}(c_1)=\kappa_{P,z}(c_2).
\]

授权发放时保存 κ(c_r)，提交时计算 κ(c_s)。两者匹配才通过本次目标检查。例子包括 instance ID 键、context 键或 canonical proposal value 键。若还有隐蔽的 target 过滤，必须计入实际目标许可关系；不能把实现的有效粒度说得比真实更粗或更细。

不是所有授权策略都形成等价关系。单向委派、按 grant 限定的候选白名单等，应改写为 Permit_P(a,c_s)。更一般的条件是：每个可达且通过 G 的 Permit_P 请求都满足责任许可；证明方法相同，但不能继续使用 partition/refinement 术语。

## 4. R：提交前的操作可达性

定义

\[
R_z=\{(h,s,a,c_s):\text{在声明的操作模型中可到达该提交前配置}\}.
\]

判定 R 的依据是创建候选、发放授权、构造请求、存储状态和接口可用性；**不使用本次请求的 P 匹配结果，不使用 A 是否满意，也不使用提交后是否安全**。否则“只把合法接受请求叫可达”会使定理自证。

z 的可达模型必须公开。对于固定候选池实验，可以直接列举请求和 receipt；对于协议模型，应写出状态转移规则。对真实系统给出的一个违反兼容性的 pair，必须能构造具体操作前缀，才能称其为该系统的可达反例。

若比较不同策略会改变过去的可接受提交，从而改变之后能到达的状态，则长期可达集合依赖策略。此时应明确写 R_{z,P}，不能假装所有策略共享同一 R；D1 仍可逐策略判定，但它不能直接导出一个与历史无关的总粒度排序。若使用对多种策略的保守可达上界 \widehat R，则上界满足兼容条件足以证明安全；上界违反条件只给出待验证的潜在反例，不能声称真实系统必有攻击。

这也说明 D1 尚未替代 D3：当前没有证明一个任意长度的实际历史保持全部责任不变量。

## 5. G：目标等价以外的准入条件

G_z(σ) 是固定、可独立检查的 guard，包含此判定中约定的其他条件，例如：授权本身有效、审阅者在合同指定的检查时点有权限、前驱版本新鲜、证据完整、批量域满足约束、拟写入值等于显式授权值。哪些 guard 已实现、哪些仅是假设，必须分别列出。

G 不得包含“提交候选等于审阅候选”或“责任规范已满足”来掩盖粒度问题。否则 exact match 被偷偷放回 G，粗粒度策略当然永远不会暴露差异。批量/字段形状等独立约束可保留，但需要公开它们实际过滤了哪些替换。

从 R 与 G 导出通过其他准入条件的候选对：

\[
\mathcal R_z^G=
\{(c_r,c_s):\exists\sigma=(h,s,a,c_s)\in R_z,
a.c_r=c_r,\ a.x_a=x_a,\ G_z(\sigma)\}.
\]

因此必须记录存在量词见证；不能先看到某 pair 被 P 接受，再把它加入可达集合。此前简写的 R_z ∩ (P\A)=∅，只有把 R_z 明确约定为这个 **guard 后的 pair 集合** 才准确。这里保留 R 和 G 两个独立对象以便审计。

## 6. D1 命题、假设及证明

**实现假设 H1（目标检查的完整描述）。** 对每个 σ∈R_z，本次准入精确满足

\[
\operatorname{Admit}_{P,z}(\sigma)
\iff G_z(\sigma)\land(c_r\sim_{P,z}c_s).
\]

这是需要由实现或实验验证的假设，不是从 safety 推出的定义。若系统有额外拒绝条件，必须把它们公开，并重新定义有效许可集合；对于仅有“接受必通过上述条件”的单向实现假设，下面的条件仍充分，但不再必要。

**责任替换安全。** 对所有 σ∈R_z，若 Admit_P,z(σ)，则 c_r∼A,z,x_a c_s。这只表达目标替换这一维的安全。

**命题 D1。** 在上述固定环境、固定授权值和 H1 下，策略具有责任替换安全，当且仅当

\[
\boxed{\mathcal R_z^G\cap
(\sim_{P,z}\setminus\sim_{A,z,x_a})=\varnothing.}
\]

**充分性。** 取任意已准入 σ。由 H1，G_z(σ) 为真，且 pair 属于 ∼P。由 R 的见证，该 pair 属于 𝓡_z^G。若不属于 ∼A，则它属于交集，违背交集为空。因此每个已准入请求都满足责任等价。

**必要性。** 若交集非空，取其中一对 (c_r,c_s)。由 𝓡_z^G 的定义，有实际模型中的提交前配置 σ，具有同一 c_r、c_s、x_a 且 G 为真。pair 属于 ∼P，故由 H1 得到准入；pair 不属于 ∼A，因此责任替换安全失败。证毕。

注意：必要性使用 H1 的反向蕴含，也使用精确的可达见证。忽略这两项会把“有风险的键碰撞”误说成“系统必然接受的错误”。拒绝所有请求的系统可以具有 safety，但无法满足此处为指定键策略设定的 H1；单独讨论 safety 时，不能假借本命题否认这种系统安全。研究还需独立衡量合法请求的覆盖或 utility。

## 7. 三个边界例子

令 C={c₁,c₂}，两者 canonical proposal、记录、字段、证据和生产者相同，instance ID 不同。授权值固定为 101，G 为真。

| 场景 | A | P | 𝓡^G 中的替换 | D1 判定及含义 |
|---|---|---|---|---|
| 实例责任下可达同上下文替换 | exact instance | context key | (c₁,c₂) 可达 | 不安全；context policy 对该责任规范不足 |
| 同一 A/P，但接口禁止第二实例进入授权后的提交路径 | exact instance | context key | 仅对角 pair | 安全；全局 P 比 A 粗仍不足以推出真实风险 |
| 应用只要求内容责任 | context responsibility | context key | (c₁,c₂) 可达 | 安全；不能把 context policy 一概定性为错误 |

这三个是定义核验用的构造场景，不是新增现实实验。第二例的可达限制必须由协议或接口证明；只因现有日志中没见到替换，不足以建立不可达性。

原 E1 的同值、同上下文替换支持第一种条件实例；实验输入明确选择了实例责任。历史 A4 同时变化 evidence hash、locator、evidence file 和 selection artifact，不能当作第一例的 identity-only 外部验证。84 条 B2 纠正则属于合法集成证据，没有提供同上下文身份替换的额外可达性见证。

## 8. 科学地位与第一阶段决定

D1 的证明是基本集合推理。加入 R 和 G 后，它避免了“严格包含就一定有实际风险”的错误，也提供了可检查的设计条件；但 **这个 iff 本身仍是对安全许可集合的重新表达，不能单独承担论文级理论创新**。不能因为增加量词和环境下标就升级 novelty。

要把框架变成实质新增知识，至少还需独立的责任规范来源、能计算或验证可达性的具体方法，或有区别于近邻工作的保持性/设计结果。现有第一阶段仅完成了定义、语义边界和证明，并没有完成这些新增结果。

当前决定：暂停把 D1 作为 authorization-granularity 新理论主贡献。优先保留可辩护的 field-correction contract + hosted-agent integration 路线；如未来启动 D3，须先明确新增不变量及其相对既有 kernel 的差异，另行评估投入。本文档不启动 D3，也不修改 manuscript。
