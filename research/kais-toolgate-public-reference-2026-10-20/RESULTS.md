# 公共参考流程中的比较结果

2026-10-20。**C 与合理配置后的 ToolGate 在本轮共同合同义务、实际提交和完整参考终态上得到相同结果。** 新证据是合同可以接入真实公共工具，并让已经提交的授权状态进入后续业务流程；本轮没有观察到 C 独有的保护优势。

## 实验单位和执行

从未参加先前三任务比较的14个候选任务出发，按共同初态和去除 action_id 后的完整动作序列去重为12组，执行前固定选择最小的六个代表：59、71、78、96、101、102。每条流程使用 corrected、reauthorized、instance_mismatch、wrong_value 四种预先固定的场景。两路各24个任务×场景组合，共48条执行，均保留。

六条参考流程都能用固定原生工具成功重放，共18个参考工具调用。任务59含四个前置调用和目标地址更新，没有后缀；其余五条包含1–2个后续动作，包括订单商品修改、其他订单取消或换货。六条流程仍有共享订单或动作，不是六个独立自然抽样。

实例替换和未采用授权值是人为构造的控制；恢复也是预先规定的脚本。它们衡量实现与接续能力，不估计自然失配频率、模型恢复率或真实人工审批成本。

## 联合结果

| 实际检查 | T-configured | C |
|---|---:|---:|
| 执行完成／工程错误 | 24／0 | 24／0 |
| 两类合法初始请求完成授权提交 | 12/12 | 12/12 |
| 两类违规初始请求被拒绝，业务状态未变 | 12/12 | 12/12 |
| 随后固定合法恢复产生提交 | 12/12 | 12/12 |
| 每路最终恰好一个新增业务版本 | 24/24 | 24/24 |
| 完整公共世界与原生参考终态一致 | 24/24 | 24/24 |
| 原生草稿工具调用总数 | 30 | 36 |
| 后缀工具调用总数 | 32 | 32 |
| 冻结评分器的全部检查 | 23 PASS、1 FAIL | 24 PASS |

最后一行的唯一 FAIL 为 P59-corrected/T-configured 首次导入原生工具时输出两条 `.env` / 数据目录日志。该记录的 SQL、授权、完整订单、来源、回调和公共终态检查均通过；原评分和日志完整保留，另见 [DIAGNOSTIC-ADJUDICATION.md](DIAGNOSTIC-ADJUDICATION.md)。不能将这个诊断差异计为 C 多拦截了一次违规，也不能静默将原始严格评分改成48 PASS。

T 的实例失配由 pre 回调在调用草稿工具前拒绝；C 适配器先调用克隆世界上的草稿工具，再送入原 C 准入，因此两路分别有30与36次草稿调用。这是本轮适配顺序的具体差异，没有测量延迟、费用或真实用户负担，不能据此推广为某一方法的性能优势。两路都各有36次准入尝试、24次最终业务提交。

每路保存完整 SQL 和逐次尝试；首次拒绝的无写入证据没有被恢复结果覆盖。成功提交后，运行器重新只读查询实际 SQLite，把订单投影回公共世界，再执行原任务的全部后缀。独立评分比较整个 `products/users/orders`，而不只比较地址。

## 对论文的实际补强

原有八项开发控制只回答有限机制能否配置。本轮进一步核实了：

1. 候选订单确实由原公共工具执行产生，完整字段进入两种实现。
2. 准入结果落实到真实 SQLite；未经授权的首次尝试不改变业务记录。
3. 经过合法提交和固定恢复后，五条带后缀的流程能继续执行；六条完整参考流程的终态均与原生参考一致。

因此可以把这组结果作为“独立执行框架上的合同适配与公共工具参考流程验证”。它不支持声称击败 ToolGate、实现独有保护、取得官方 benchmark 成功率或证明统计等效。任务中的 NL_ASSERTION、真实对话和官方评价器没有执行；后缀是普通公共工具调用，不额外声称它们受到地址合同保护。主线外新增防御场景为0。

这轮已提供与拒稿意见直接相关的方法比较和外部流程证据。继续重复同类控制对新增知识帮助有限；下一步应把近邻已有保证、本文明确提出的关系以及这些实测结果对应起来，形成准确的新稿论证。自然失配或人工审批收益属于另一种证据问题，不能用本轮脚本成功率代替。
