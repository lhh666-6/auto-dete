# Failure handling and resume

Transient provider timeouts, URL failures, mid-read reset/abort, truncated response or HTTP 429/5xx: keep each raw attempt, max two outer retries, waits 2/8 seconds bounded by Retry-After and remaining request/run budget. No semantic action has run yet. HTTP auth/balance/model-unavailable or malformed provider envelope terminate as recorded runtime failure; no model replacement. Native CLI reconnects remain distinct. A single malformed action can receive only the inherited generic format feedback; no task-specific repair hints.

Successful semantic commit consumes grant exactly once. A returned receipt replay with identical key/arguments does not mutate again. An uncertain host outcome is logged with actual persisted state; Agent can inspect state or retry identical arguments under same idempotency key. Never assume a connection loss means no commit. CAPABILITY_UNAVAILABLE is task feedback, not transport retry. Stale/evidence/instance rejections are actual workflow events passed to subsequent Agent decisions, never a reason to restart task.

Completed/failed terminal pairs are immutable and never selectively rerun. --resume skips terminal pairs; a completed pair independently verifies its artifacts. Per-decision safe-boundary checkpoints atomically retain original messages, pending feedback, state and used counters. A received response cached at a safe boundary is reused without model resampling. An interrupted in-flight provider request can consume only remaining transport attempts. Elapsed wall time includes offline downtime and existing budgets are not refreshed.

If interruption occurs inside a semantic action before a complete safe boundary, retain raw events and durable SQLite state, finalize with INTERRUPTED_SEMANTIC_STEP, no action reexecution and no rollback to a prior boundary. Missing boundary at an already initialized arm is RESUME_BOUNDARY_MISSING and no empty-history sampling. Incomplete log/state proof yields unknown; a covered proved violation still yields I=0. Process-kill recovery thus supports safe resumption, not unlimited transparent restarts. Unexpected code/audit exceptions pause the batch for inspection while retaining every planned arm. One OS-held collection lock prevents a second coordinator; it releases on process death.

Observable provider alias/revision or CLI-version change pauses both provider lanes; another in-flight HTTP call can finish but the next Agent decision boundary stops. No following pair starts. Preserve interrupted/affected records, investigate deployment, version bump and new freeze when scientific inputs change. --resume alone does not authorize replacing deployments or redoing terminal pairs. Scientific design bugs always stop collection, retain old batch and require version bump/re-freeze. No deletion, selective rerun, prompt/scorer/budget change, post-hoc missing conversion, scenario adjustment or p-value sample expansion.
